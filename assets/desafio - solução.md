# Challenge — solution

| Problem | Implemented solution |
|---|---|
| Answer recurring questions accurately without relying on the model's memory or creativity. | The agent uses function calling: the model chooses the tool, but prices, inventory, orders, promotions, shipping, and delivery times come from deterministic data queries. |
| The data contained inconsistencies that could produce wrong answers: active products with no stock, discontinued products with stock, “coming soon” items in orders, and totals that differed from the sum of items. | Data loading derives availability from status and stock, keeps the order total as the official value, and handles each product state explicitly. |
| Expired promotions could be offered, and the discount did not follow the product. | Only active promotions are returned, with the original price, percentage, promotional price, and effective price. Price filters use the effective value. |
| The policy manual was a PDF with truncated sections, literal search, extraction noise, and conflicting rules. | The PDF is converted into clean, versioned Markdown, split into main sections and subsections, with topic aliases and the full manual injected into the system prompt. |
| Business rules involved calculations and decisions that small models can easily get wrong: PIX, installments, shipping, and deadlines. | PIX, installment plans, shipping, and deadlines are calculated in code. The model only presents the result and does not perform arithmetic. |
| The dataset does not contain the actual receipt date, which is needed to calculate return and warranty eligibility. | A configurable reference date (`REFERENCE_DATE`) was added. The 7-, 30-, and 90-day periods use the estimated delivery date as the documented basis. |
| Catalog search failed with plurals, accents, categories, and model codes, and generated false positives. | Search is normalized and now considers name, description, category, and specifications, with singular/plural handling and matching by words or model codes. |
| Order lookup could expose data to anyone who knew only the customer's name or order number. | Validation accepts only email or phone, compares digits only, requires the phone when an email is shared, and returns the same generic message for nonexistent orders and incorrect details. |
| The order response did not show items or say whether the customer could still return or exchange the order. | The lookup returns items, the official total, days since estimated delivery, and eligibility for withdrawal, defect exchange, and the legal warranty, without exposing the account holder's contact details. |
| Tool failures, invalid arguments, or provider instability could end the conversation. | The dispatcher uses a tool whitelist, validates arguments with Pydantic, returns errors to the model, and handles API failures with a friendly message. The loop has an iteration limit. |
| Free models can vary in behavior, provider, and tool-calling support. | The model and provider are fixed through environment variables, with no random fallback. A tool-calling smoke test was added, and critical calculations remain in code. |
| The model could forget rules in long conversations or repeat contradictory information from the manual, such as the phone number, email, and instrument quantity. | The full manual is included in the system prompt, with explicit notes about the primary contact, correct email, installments, and warranty. The agent does not repeat unverifiable catalog numbers. |
| The agent could answer out-of-scope topics or invent information. | The prompt defines the persona, grounding, polite out-of-scope refusal, and prohibition against inventing data. When a tool finds nothing, the agent states that explicitly. |
| Model responses were in Markdown, but the terminal displayed raw markers. | The CLI renders Markdown with `rich`, displaying tables, lists, bold text, and headings legibly in the terminal. |
| The project needed to be executable, testable, and reproducible by another person. | A complete README, `.env.example`, `Makefile`, versioned manual cache, and a 28-test suite were added, including agent orchestration with a fake client and a real provider smoke test. |
| The challenge requires interaction examples and documentation of decisions. | Five conversation examples were included, covering catalog, store information, price and promotion, returns, and out-of-scope requests, along with assumptions and limitations in the README. |
